# Candidate Pipeline Dashboard

Dashboard פשוט בעברית (RTL) לניהול לידים ומועמדים: מי צריך Follow-up, מה הסטטוס, ומה הפעולה הבאה.
האפיון המלא נמצא ב-[SPEC.md](SPEC.md).

## טכנולוגיה

- הדף: HTML, CSS ו-JavaScript בלבד, ללא Frameworks וללא שלב Build.
- שרת מקומי (`server.py`): Python 3.9 ומעלה, ספרייה סטנדרטית בלבד (בלי `pip install`). הוא נדרש רק לייבוא מידע מהרשת דרך Apify.
- הנתונים נשמרים בדפדפן (`localStorage`):
  - `candidatePipeline.leads.v1`: הלידים.
  - `candidatePipeline.enrichment.v1`: מידע שיובא מהרשת וקישורי פרופיל.
  - `candidatePipeline.airtableToken` ו-`candidatePipeline.lastSync`: מפתח Airtable ומועד הסנכרון האחרון.
- הגופן Heebo נטען מ-Google Fonts. בלי חיבור לאינטרנט יוצג גופן מערכת.

## הרצה מקומית

הדרך המומלצת היא דרך השרת המקומי, כי רק כך עובד ייבוא המידע מהרשת. מריצים מתיקיית הפרויקט:

```bash
python server.py
```

ואז גולשים ל-`http://localhost:8000`. הפורט ניתן לשינוי עם `PORT` בקובץ `.env`.

אפשר גם לפתוח את `index.html` ישירות, או להשתמש בגרסה שב-GitHub Pages. הדשבורד והסנכרון מ-Airtable עובדים גם כך, אבל ייבוא המידע מהרשת לא זמין.

### הגדרת Apify (פעם אחת)

1. פותחים חשבון ב-[apify.com](https://apify.com). המסלול החינמי כולל קרדיט חודשי.
2. מעתיקים את ה-API token מ-**Settings → API & Integrations** ב-[console.apify.com](https://console.apify.com/settings/integrations).
3. בתיקיית הפרויקט יוצרים קובץ בשם **`.env`** בדיוק. אפשר להעתיק את `.env.example`, אבל צריך לשנות את השם של העותק.
   - שימו לב: ב-Windows, "העתק/הדבק" יוצר קובץ בשם `.env - Copy.example`, והשרת לא קורא אותו.
4. בקובץ כותבים `APIFY_TOKEN=` ואחריו הטוקן, ושומרים.
5. מפעילים מחדש את `python server.py`. בשורת הפתיחה צריך להופיע `Apify token configured: yes`.

הטוקן נשאר בשרת בלבד: הוא לא נשלח לדפדפן, לא נכתב ללוג, ו-`.env` מופיע ב-`.gitignore`.

## איך לבדוק

1. בפתיחה ראשונה נטענים 12 לידים לדוגמה (פרטים פיקטיביים), כולל Follow-up להיום ו-Follow-up באיחור.
2. "הוסף ליד": הוספת ליד (שם הוא שדה חובה).
3. "עריכה" / "מחיקה" בכל שורה. לפני מחיקה מוצגת הודעת אישור.
4. חיפוש לפי שם, טלפון (גם בלי מקפים) או אימייל. סינון לפי סטטוס, רמת עניין ו-Follow-up.
5. לחיצה על כרטיס סיכום מסננת את הטבלה בהתאם.
6. רענון הדף: הנתונים נשמרים.
7. "איפוס לנתוני דוגמה" (בתחתית הדף) מוחק את השינויים וטוען מחדש את נתוני הדוגמה.
8. "Sync מ-Airtable": בפעם הראשונה מזינים מפתח גישה, ואחרי אישור הלידים מ-Airtable מחליפים את הנתונים בדשבורד.
9. לחיצה על שם ליד פותחת את עמוד הפרטים. באזור "מידע מהרשת" אפשר לשמור קישור ל-Instagram, ולייבא באמצעות Apify אחרי אישור העלות. לשם כך צריך את השרת המקומי ואת הגדרת Apify.
10. "תחזית ים": בוחרים חדרה, נתניה או תל אביב, ובודקים כרטיסים, גרף וטבלה שעתית. הכפתור "רענון" שולף מחדש. העמוד עובד גם בלי השרת המקומי.

## סנכרון מ-Airtable

הכפתור "Sync מ-Airtable" טוען את הלידים מהטבלה "לידים" בבסיס "Candidate Pipeline" ב-Airtable.

- **כיוון אחד:** הנתונים עוברים מ-Airtable לדשבורד בלבד. עריכות בדשבורד (וגם "שימוש במידע מהרשת") **לא** נשמרות ב-Airtable, אלא רק בדפדפן.
  - ליד שנערך בדשבורד מסומן "נערך מקומית".
  - טופס העריכה מציין שהשינוי נשמר בדפדפן בלבד.
- **החלפה:** הסנכרון מחליף את כל הלידים בדשבורד בנתונים מ-Airtable. לפני ההחלפה מוצגת הודעת אישור עם מספר הלידים ואזהרה על מה שיאבד:
  - לידים שנערכו מקומית.
  - לידים שקיימים רק בדשבורד.
- **מה מוצג בכל רגע:** הדשבורד מציג את הנתונים כפי שנשמרו בדפדפן בסנכרון האחרון (המועד מוצג בתחתית הדף). רענון הדף לא פונה ל-Airtable. כדי לקבל שינויים שנעשו ב-Airtable לוחצים Sync.
- **כל הרשומות:** הקריאה עוברת על כל העמודים של Airtable (עד 100 רשומות לבקשה). יש מגבלת בטיחות של 50 עמודים (5,000 רשומות).
- **שגיאות:**
  - מפתח שגוי (401), או בלי הרשאה / טבלה לא נמצאה (403/404): הודעה מתאימה, והמפתח נמחק.
  - יותר מדי בקשות (429), Airtable לא זמין (5xx), בעיית רשת או תשובה לא צפויה: הודעה מתאימה, המפתח נשמר.
  - בכל מקרה של שגיאה הנתונים בדשבורד לא משתנים.
- **מפתח גישה:** בפעם הראשונה מתבקשים להזין מפתח גישה אישי (Personal Access Token) של Airtable.
  - יוצרים אותו ב-[airtable.com/create/tokens](https://airtable.com/create/tokens), עם ההרשאה `data.records:read` וגישה לבסיס "Candidate Pipeline" בלבד.
  - המפתח נשמר רק בדפדפן שבו הוזן (`localStorage`). הוא לא נמצא בקוד ולא ב-GitHub.
  - הקישור "ניתוק מ-Airtable" בתחתית הדף מוחק את המפתח מהדפדפן.
  - אם Airtable דוחה את המפתח (שגוי, פג תוקף או בלי גישה לבסיס), המפתח נמחק, ובלחיצה הבאה מתבקשים להזין מפתח חדש.
- **מיפוי:** השדות נקראים לפי מזהי השדות ב-Airtable, ולכן שינוי שם של שדה ב-Airtable לא ישבור את הסנכרון. מזהי הבסיס, הטבלה והשדות מוגדרים ב-`AIRTABLE` בתוך `js/app.js`.
- **ערכים לא מוכרים:** רשומה בלי שם מדולגת. סטטוס או רמת עניין שהדשבורד לא מכיר מקבלים ערך ברירת מחדל ("ליד חדש", "לא ידוע"). תאריך לא תקין נשאר ריק. בכל המקרים האלה מוצגת הערה בהודעת האישור.

## עמוד פרטי ליד ו"מידע מהרשת"

לחיצה על שם ליד בטבלה פותחת את עמוד פרטי הליד (כתובת בצורה `#lead/<id>`). הכפתור "→ חזרה לדשבורד", או כפתור "אחורה" בדפדפן, מחזירים לטבלה.

- **פרטי הליד:** כל השדות, מקור הליד (Airtable או מקומי) ומועד הסנכרון. הכפתור "עריכת פרטים" פותח את טופס העריכה הרגיל.
- **מידע מהרשת (Instagram, דרך Apify):** מידע ציבורי מפרופיל Instagram. הוא **מיובא רק בלחיצה** על "ייבוא באמצעות Apify", ולא אוטומטית בפתיחת הליד.
  - **קישור לפרופיל:** אפשר להזין ולשמור קישור (או `@username`). אם יש קישור, הייבוא רץ עליו בעזרת [Instagram Profile Scraper](https://apify.com/apify/instagram-profile-scraper).
  - **חיפוש לפי שם:** אם אין קישור, הייבוא מחפש פרופילים לפי השם בעזרת [Instagram Search Scraper](https://apify.com/apify/instagram-search-scraper) ומציג עד 5 התאמות **לבחירה**.
    - שום פרופיל לא משויך לליד בלי בחירה ואישור מפורשים.
    - מוצגת אזהרה ששם זהה לא מוכיח שזה אותו אדם.
  - **לפני כל הרצה בתשלום** מוצגת העלות הצפויה, שנקראת בזמן אמת מ-Apify, ותקרת חיוב קשיחה. ההרצה מתחילה רק אחרי אישור. התקרות: $0.01 לפרופיל ו-$0.03 לחיפוש. Apify עוצר הרצה שמגיעה לתקרה.
  - **עלות בפועל** (נבדק בהרצות אמיתיות, מסלול FREE):
    - פרופיל: $0.0026.
    - חיפוש עם 5 תוצאות: $0.0135.
    - **גם פרופיל שלא נמצא מחויב ($0.0026)**, כי ה-Actor כותב לתוצאות שורת שגיאה `not_found`.
    - העלות מחושבת מאירועי החיוב ש-Apify רשם, והשרת ממתין כמה שניות עד שהחיוב נרשם.
  - **מצבים:** טעינה, הצלחה (עם העלות בפועל לפי Apify), אין תוצאות, שגיאה. השגיאות כוללות: אין שרת, אין טוקן, טוקן שגוי, אין קרדיט, הרצה שנכשלה או שנמשכה יותר מדי.
  - **הפרדה מפרטי הליד:** המידע שיובא מוצג בכרטיס נפרד, עם קישור למקור, מועד הייבוא ועלות ההרצה. הוא נשמר בנפרד (`candidatePipeline.enrichment.v1`), כך ש-Sync מ-Airtable לא מוחק אותו ולא מערבב אותו בפרטי הליד.
  - **בלי דריסה:** הוא לא משנה את פרטי הליד. אפשר לבחור במפורש "החלפת שם הליד" או "הוספת הביוגרפיה והקישור להערות". כל אחת מהן מציגה את הערך הקיים מול החדש ומבקשת אישור.
- **אבטחת השרת:**
  - השרת מאזין רק למחשב המקומי (`127.0.0.1`).
  - הוא מגיש רק את קבצי האתר: לא את `.env`, לא את `server.py` ולא את `.git`.
  - הוא מריץ רק את שני ה-Actors האלה, ומקבל בקשות הרצה רק מהאתר עצמו. אתר אחר שפתוח בדפדפן לא יכול להוציא קרדיט.

## תחזית ים (Open-Meteo)

עמוד `forecast.html` נפתח מהכפתור "תחזית ים" בראש הדשבורד. הכפתור "→ חזרה לדשבורד" מחזיר לטבלה. העמוד מציג תחזית שעתית ל-48 השעות הקרובות של **גובה גלים** (מטרים), **כיוון גלים** (מעלות, הכיוון שממנו הגלים מגיעים) ו**מחזור גלים** (שניות), לשלושה אזורי חוף.

- **החיבור:**
  - הדפדפן פונה ישירות ל-[Open-Meteo Marine Weather API](https://open-meteo.com/en/docs/marine-weather-api) (`https://marine-api.open-meteo.com/v1/marine`).
  - בלי טוקן ובלי שרת: השירות חינמי לשימוש לא מסחרי ומאפשר פניות מהדפדפן (CORS), ולכן העמוד עובד גם ב-GitHub Pages וגם כשפותחים את הקובץ ישירות.
  - הפרמטרים בכל בקשה:

    ```text
    hourly=wave_height,wave_direction,wave_period
    timezone=Asia/Jerusalem
    forecast_hours=48
    cell_selection=sea
    length_unit=metric
    ```

- **קואורדינטות:** נקודות בים, כ-2 ק"מ מערבית לכל חוף.
  - מודל הגלים בנוי מתאים של כ-8 ק"מ. נקודה על קו החוף נופלת בתא יבשה, ושם ה-API מחזיר ערכים ריקים (נבדק).
  - `cell_selection=sea` גורם ל-API להשתמש בתא הים הקרוב. העמוד מציג גם את הנקודה המבוקשת וגם את תא המודל שה-API החזיר.

  | מיקום | נקודה מבוקשת בים | תא המודל שה-API החזיר | מרחק מהנקודה |
  |---|---|---|---|
  | חדרה | 32.470°N, 34.850°E | 32.458°N, 34.792°E | 5.6 ק"מ |
  | נתניה | 32.330°N, 34.825°E | 32.292°N, 34.792°E | 5.3 ק"מ |
  | תל אביב | 32.085°N, 34.745°E | 32.125°N, 34.708°E | 5.6 ק"מ |

- **תצוגה:**
  - כרטיסים: גובה גלים, כיוון ומחזור לשעה הנוכחית, ושיא הגובה ב-48 השעות.
  - גרף גובה גלים לפי שעה, וטבלה שעתית מלאה.
  - כל הזמנים באזור הזמן `Asia/Jerusalem`, גם אם הדפדפן מוגדר לאזור זמן אחר.
  - מוצגים: שם המיקום, קישור למקור ומועד השליפה האחרון.
  - המיקום האחרון נזכר, וגם הכתובת `forecast.html#netanya` פותחת ישירות את נתניה.
- **מצבים:** טעינה, רענון, שגיאה ונתונים חסרים.
  - שגיאה מטופלת לפי סוג: שגיאת API עם הסיבה שהחזיר, בעיית רשת, תשובה לא צפויה, או חוסר תגובה במשך 15 שניות.
  - **ערך חסר מוצג "אין נתון" ומופיע כרווח בגרף, אף פעם לא כאפס.**
- **מעבר בין מיקומים:**
  - הבקשה הקודמת מבוטלת, ולכל בקשה יש מספר רץ. תשובה מאוחרת של מיקום קודם לא תוצג עבור המיקום החדש.
  - במעבר מיקום הנתונים הקודמים מוסתרים מיד.
- **קרדיט ורישיון:**
  - הנתונים מסופקים ברישיון CC BY 4.0.
  - ליד הנתונים מופיע הקישור [Weather data by Open-Meteo.com](https://open-meteo.com/), כפי ש-Open-Meteo דורשים, עם קישור לרישיון ולמקורות הנתונים.
  - הערכים עוגלו לתצוגה.
- **אזהרה:** המידע הוא תחזית ממודל, ודיוקו ליד החוף מוגבל. **הוא לא מיועד לניווט ימי או להחלטות בטיחות.** ההערה הזו מופיעה גם בעמוד.

## מגבלות ידועות

- **Apify דורש את שרת ה-Python (`server.py`) ולא עובד דרך GitHub Pages בלבד.**
  - הטוקן של Apify חייב להישאר בצד השרת, ו-GitHub Pages מגיש קבצים סטטיים בלבד.
  - באתר המפורסם הדשבורד והסנכרון מ-Airtable עובדים, אבל אזור "מידע מהרשת" מציג הודעה שהייבוא זמין רק דרך השרת המקומי.
  - כדי שהייבוא יעבוד אונליין, צריך להעלות את `server.py` לשירות שמריץ Python, עם `APIFY_TOKEN` כמשתנה סביבה. זה לא בוצע.
- **הסנכרון מ-Airtable הוא בכיוון אחד.**
  - עריכות בדשבורד, לידים שנוספו בו ושימוש במידע מהרשת נשמרים בדפדפן בלבד. Sync מוחק אותם, אחרי אזהרה.
  - כתיבה חזרה ל-Airtable תדרוש מפתח עם הרשאת כתיבה ושרת שיחזיק אותו.
- **הכול נשמר ב-`localStorage` של הדפדפן:** הנתונים, המידע מהרשת ומפתח Airtable. לכן הם לא עוברים בין מחשבים או דפדפנים.
- **Instagram בלבד.** רק פרופילים ציבוריים. הסריקה תלויה ב-Actors של Apify ובשינויים ב-Instagram.
- **קישורי תמונות הפרופיל** מ-Instagram פגים אחרי זמן מה. תמונה שלא נטענת מוסתרת.
- **תחזית ים:**
  - רזולוציית המודל כ-8 ק"מ, ולכן תא המודל רחוק כ-5–6 ק"מ מהנקודה המבוקשת וכ-7–8 ק"מ מהחוף.
  - הנתונים לא נשמרים: כל פתיחה או רענון שולפים מחדש.
  - השירות החינמי מוגבל ל-10,000 בקשות ביום ולשימוש לא מסחרי.
- **טבלת הלידים** רחבה ברוחב מסך של כ-1,400 פיקסלים ומטה, בעיקר כשלידים רבים מסומנים "באיחור". במקרה כזה היא נגללת לרוחב בתוך המסגרת שלה.
- **מצבי שגיאה שלא נבדקו בהרצה אמיתית:**
  - Airtable: מגבלת קצב (429), תקלת שרת (5xx) ונפילת רשת. הם נבדקו בסימולציה בלבד.
  - Apify: "אין קרדיט", הרצה שנכשלה והרצה ארוכה מדי. הם מומשו בקוד, אבל לא הופעלו בפועל.

## הסרת כפילויות

- הכפתור "הסרת כפילויות" בראש הדף מוצא לידים ש**כל הפרטים שלהם זהים** לליד אחר: שם, טלפון, אימייל, מקור, סטטוס, רמת עניין, תאריכים, פעולה הבאה והערות.
- כשיש כפילויות, המספר שלהן מוצג על הכפתור, למשל "הסרת כפילויות (3)".
- לפני המחיקה מוצגת הודעת אישור. מכל קבוצה של לידים זהים נשאר הליד הראשון שנוסף, והעותקים הנוספים נמחקים.
- ליד שאפילו שדה אחד שלו שונה לא נחשב כפילות ולא נמחק. גם `050-1234567` ו-`0501234567` נחשבים שונים.
- מצב שבו זה שימושי: ליד שנוסף פעמיים בטעות, עם אותם פרטים בדיוק.

## ייבוא וייצוא CSV (הוסרו מהממשק)

הכפתורים "ייצוא ל-CSV" ו"ייבוא מ-CSV" הוסרו מהממשק, כי מקור הנתונים הוא עכשיו Airtable (ראו "סנכרון מ-Airtable").
הקוד עצמו (`js/csv.js` והחלק המתאים ב-`js/app.js`) עדיין נמצא בפרויקט, ולכן קל להחזיר את הכפתורים אם יהיה בהם צורך.

## כללים שנקבעו בגרסה הראשונה

- **Follow-up נדרש**: ליד פתוח שתאריך ה-Follow-up שלו הוא היום או שכבר עבר. ליד פתוח הוא ליד שאינו "נסגר בהצלחה" ואינו "לא רלוונטי".
- **לידים בתהליך**: הסטטוסים נוצר קשר, נשלח מידע, שיחה התקיימה, Follow-up, מתלבט.
- **הסטטוס "נשלח מידע"** נוסף מעבר לשמונת הסטטוסים שבאפיון, כי הוא קיים בנתונים ב-Airtable.
- **סדר הטבלה**: Follow-up באיחור, אחריו היום, אחריו עתידי, אחריו ללא תאריך. לידים סגורים או לא רלוונטיים מוצגים בסוף.
- תאריכי נתוני הדוגמה נקבעים יחסית ליום ההפעלה הראשונה.

## פרסום ב-GitHub Pages

1. ליצור Repository חדש ב-GitHub ולהעלות אליו את קבצי הפרויקט (`index.html` צריך להיות בתיקייה הראשית).
2. ב-Repository: **Settings → Pages**.
3. תחת **Source** לבחור **Deploy from a branch**, ענף `main`, תיקייה `/ (root)`, ולשמור.
4. אחרי כדקה האתר יהיה זמין בכתובת `https://<username>.github.io/<repo-name>/`.

שימו לב:
- הנתונים שמוצגים בדשבורד נשמרים בדפדפן של כל משתמש בנפרד. מקור הנתונים המשותף הוא Airtable, וכדי לקבל את הנתונים העדכניים לוחצים על "Sync מ-Airtable".
- GitHub Pages מגיש קבצים סטטיים בלבד, ולכן אין שם את `server.py`. באתר המפורסם, אזור "מידע מהרשת" מציג הודעה שהייבוא זמין רק דרך השרת המקומי.
