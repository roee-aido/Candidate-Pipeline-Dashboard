# Candidate Pipeline Dashboard

Dashboard פשוט בעברית (RTL) לניהול לידים ומועמדים: מי צריך Follow-up, מה הסטטוס, ומה הפעולה הבאה.
האפיון המלא נמצא ב-[SPEC.md](SPEC.md).

## טכנולוגיה

- HTML, CSS ו-JavaScript בלבד, ללא Frameworks וללא שלב Build.
- הנתונים נשמרים בדפדפן (`localStorage`), תחת המפתח `candidatePipeline.leads.v1`.
- הגופן Heebo נטען מ-Google Fonts. בלי חיבור לאינטרנט יוצג גופן מערכת.

## מבנה הקבצים

```text
index.html      מבנה הדף: כרטיסי סיכום, סינון, טבלה וטופס
css/style.css   עיצוב, צבעי סטטוסים, התאמה למובייל
js/csv.js       פונקציות כלליות לכתיבה ולקריאה של קובצי CSV
js/app.js       נתונים, שמירה, סינון, הוספה, עריכה, מחיקה וייבוא/ייצוא CSV
SPEC.md         אפיון הפרויקט
Practice.md     תיעוד תהליך העבודה (הגשת קורס)
```

## הרצה מקומית

אפשרות 1: לפתוח את `index.html` ישירות בדפדפן (Chrome / Edge) בלחיצה כפולה.

אפשרות 2 (מומלץ): להריץ שרת מקומי פשוט מתיקיית הפרויקט, ולגלוש ל-`http://localhost:8000`:

```bash
python -m http.server 8000
```

או, אם Node.js מותקן:

```bash
npx serve .
```

## איך לבדוק

1. בפתיחה ראשונה נטענים 12 לידים לדוגמה (פרטים פיקטיביים), כולל Follow-up להיום ו-Follow-up באיחור.
2. "הוסף ליד": הוספת ליד (שם הוא שדה חובה).
3. "עריכה" / "מחיקה" בכל שורה. לפני מחיקה מוצגת הודעת אישור.
4. חיפוש לפי שם, טלפון (גם בלי מקפים) או אימייל. סינון לפי סטטוס, רמת עניין ו-Follow-up.
5. לחיצה על כרטיס סיכום מסננת את הטבלה בהתאם.
6. רענון הדף: הנתונים נשמרים.
7. "איפוס לנתוני דוגמה" (בתחתית הדף) מוחק את השינויים וטוען מחדש את נתוני הדוגמה.
8. "ייצוא ל-CSV", ואחר כך "ייבוא מ-CSV" עם הקובץ שיוצא: הלידים מתווספים שוב, והעברית נשמרת.

## הסרת כפילויות

- הכפתור "הסרת כפילויות" בראש הדף מוצא לידים ש**כל הפרטים שלהם זהים** לליד אחר: שם, טלפון, אימייל, מקור, סטטוס, רמת עניין, תאריכים, פעולה הבאה והערות.
- כשיש כפילויות, המספר שלהן מוצג על הכפתור, למשל "הסרת כפילויות (3)".
- לפני המחיקה מוצגת הודעת אישור. מכל קבוצה של לידים זהים נשאר הליד הראשון שנוסף, והעותקים הנוספים נמחקים.
- ליד שאפילו שדה אחד שלו שונה לא נחשב כפילות ולא נמחק. גם `050-1234567` ו-`0501234567` נחשבים שונים.
- מצב שבו זה שימושי: ייבוא אותו קובץ CSV פעמיים.

## ייבוא וייצוא CSV

### ייצוא ("ייצוא ל-CSV")

- כל הלידים השמורים מיוצאים לקובץ `leads-YYYY-MM-DD.csv`. הייצוא כולל את כל הלידים, גם כשמופעל סינון.
- הקובץ נשמר בקידוד UTF-8 עם BOM, כדי ש-Excel יזהה את הקידוד ויציג עברית תקינה.
- כותרות העמודות בעברית, לפי הסדר: שם, טלפון, אימייל, מקור הליד, סטטוס, רמת עניין, תאריך שיחה אחרונה, תאריך Follow-up, פעולה הבאה, הערות.
- סטטוס ורמת עניין מיוצאים כטקסט בעברית (למשל "פגישה נקבעה"). תאריכים מיוצאים בפורמט `YYYY-MM-DD`.
- המזהה הפנימי של כל ליד לא מיוצא. בייבוא נוצר לכל ליד מזהה חדש.
- ערך שמתחיל ב-`=`, `+`, `-` או `@` מקבל גרש (`'`) בתחילתו, כדי ש-Excel לא יריץ אותו כנוסחה. מספרי טלפון כמו `+972-50-1234567` לא משתנים. בייבוא הגרש מוסר.

### ייבוא ("ייבוא מ-CSV")

- השורה הראשונה בקובץ חייבת להיות שורת כותרות, ולכלול לפחות עמודת **"שם"**.
- הדרך הפשוטה ליצור קובץ תקין: לייצא קובץ מהמערכת ולהשתמש בו כתבנית.
- כותרות מוכרות: הכותרות בעברית שלמעלה, וגם שמות השדות באנגלית (`name`, `phone`, `email`, `source`, `status`, `interest`, `lastCallDate`, `followUpDate`, `nextAction`, `notes`). סדר העמודות לא משנה.
- כל העמודות מלבד "שם" אופציונליות. עמודה חסרה או תא ריק נשארים ריקים. ברירת המחדל לסטטוס היא "ליד חדש", ולרמת עניין "לא ידוע".
- שורות בלי שם מדולגות, ומספרי השורות מוצגים בהודעת האישור.
- סטטוס או רמת עניין לא מוכרים מקבלים ערך ברירת מחדל. תאריך לא תקין נשאר ריק. במקרים האלה מוצגת הערה בהודעת האישור.
- תאריכים נתמכים: `YYYY-MM-DD`, `DD/MM/YYYY`, `DD.MM.YYYY` (יום לפני חודש, כמו ש-Excel שומר בהגדרות עבריות).
- מפריד עמודות: פסיק או נקודה-פסיק. המפריד מזוהה אוטומטית, כי Excel שומר לפעמים עם נקודה-פסיק.
- לפני השמירה מוצגת הודעת אישור עם מספר הלידים שיובאו. הלידים **מתווספים** לקיימים, אין מחיקה או החלפה, ואין בדיקת כפילויות.
- קובץ שאינו תקין (סיומת שאינה `.csv`, קובץ ריק, אין עמודת "שם", אין שורות נתונים, קובץ מעל 2MB) לא מיובא, ומוצגת הודעה שמסבירה למה.

**הערה על Excel:** מספר טלפון בלי מקפים (למשל `0501234567`) עלול לאבד את ה-0 בהתחלה כשהקובץ נפתח ונשמר מחדש ב-Excel. מספרים עם מקפים (`050-1234567`) נשמרים כמו שהם.

## כללים שנקבעו בגרסה הראשונה

- **Follow-up נדרש**: ליד פתוח שתאריך ה-Follow-up שלו הוא היום או שכבר עבר. ליד פתוח הוא ליד שאינו "נסגר בהצלחה" ואינו "לא רלוונטי".
- **לידים בתהליך**: הסטטוסים נוצר קשר, שיחה התקיימה, Follow-up, מתלבט.
- **סדר הטבלה**: Follow-up באיחור, אחריו היום, אחריו עתידי, אחריו ללא תאריך. לידים סגורים או לא רלוונטיים מוצגים בסוף.
- תאריכי נתוני הדוגמה נקבעים יחסית ליום ההפעלה הראשונה.

## פרסום ב-GitHub Pages

1. ליצור Repository חדש ב-GitHub ולהעלות אליו את קבצי הפרויקט (`index.html` צריך להיות בתיקייה הראשית).
2. ב-Repository: **Settings → Pages**.
3. תחת **Source** לבחור **Deploy from a branch**, ענף `main`, תיקייה `/ (root)`, ולשמור.
4. אחרי כדקה האתר יהיה זמין בכתובת `https://<username>.github.io/<repo-name>/`.

שימו לב: הנתונים נשמרים בדפדפן של כל משתמש בנפרד. הם לא משותפים בין מחשבים ולא נשמרים בשרת.
